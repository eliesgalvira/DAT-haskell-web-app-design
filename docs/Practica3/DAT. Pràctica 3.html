    Web Application Interface

    En Haskell es disposa d'un API bàsic per a la programació d'aplicacions WEB que és independent del servidor. Aquest API s'anomena Web Application Interface (WAI) i serà el suport per a frameworks més elaborats que facilitin el desenvolupament d'aplicacions complexes.

    Podeu llegir una introducció al WAI on es descriu l'objectiu d'aquesta API i alguns senzills casos d'us.

    Exemples d'us del Web Application Interface (WAI):

    • wai-intro/holamon.hs: primer exemple.
    • wai-intro/acumulador0.hs: simple aplicació que manté una variable global de tipus enter. Es mostra un formulari que permet sumar una qüantitat.
    • wai-intro/acumulador.hs: mateixa aplicació però usant un paquet de generació d'HTML.

    • wai-intro/hello-1.hs: simple aplicació en que es mostra un formulari a l'usuari per introduir el seu nom, i guarda durant la sessió (a través d'una cookie) el nom i el mostra en les successives interaccions.

      Aquest exemple a més usa també un paquet de generació d'HTML.

    Per executar un d'aquests exemples caldrà que feu:

    ~/dat-prj$ stack runghc wai-intro/nomxFitxer.hs

    on nomFitxer.hs és el nom del fitxer corresponent al mòdul Main de l'aplicació.

    Realització d'un monad Handler

    L'objectiu d'aquest apartat és la realització d'un monad (que anomenarem Handler) que faciliti la programació d'aplicacions WEB.

    Un exemple d'us d'aquest monad el teniu en una segona versió de l'aplicació hello anterior (web-handler/hello-2.hs).

    Codi a completar

    El codi de l'aplicació (servidor WEB) es troba en el directori web-handler del projecte i conté el paquet web-handler amb els següents mòduls Haskell:

    Main
    És pròpiament l'aplicació. Conté el punt d'entrada del servidor, el codi corresponent al processat de les peticions i la generació d'HTML. (Observació: El fitxer hello-2.hs conté el mòdul Main i és l'únic en que el nom del fitxer i del mòdul poden ser diferents).
    Handler
    Defineix un monad Handler, usat pel mòdul anterior, que simplifica l'aplicació. Es l'unic mòdul que s'ha de completar.

    A més s'usen altres paquets preinstal.lats de la plataforma Haskell. Alguns dels paquets usats en aquesta aplicació, específics per a la programació de la WEB, són:

    blaze-html
    Defineix tipus, funcions i operadors per a la la generació d'HTML.
    wai
    Definició del WAI. Defineix tipus i funcions per al processat de peticions i contrucció de respostes HTTP.

    La documentació de tots els paquets la podeu trobar en https://hackage.haskell.org/, que és la base de dades centralitzada dels paquets disponibles de Haskell de codi obert. També podeu usar el buscador de funcions https://hoogle.haskell.org/ (molt útil !).

    Per completar el mòdul Handler.hs caldrà aplicar els coneixements adquirits a classe de teoria. Observeu que els efectes del monad Handler consistiran en una combinació dels efectes d'un monad Reader i d'un monad State, amb la diferència de que l'execució del monad consistirà en executar una accio IO. Observeu la definició del tipus Handler:

    newtype Handler a = HandlerC (Request -> HandlerState -> IO (a, HandlerState))

    Per facilitar el codi que s'ha de completar es donen ja fetes les definicions d'algunes funcions. Caldrà doncs entendre el codi ja donat en aquest mòdul i que servirà de guia per a la vostra solució.

    Realització del Handler amb monad transformers

    Observeu com el tipus Handler a definit anteriorment (fitxer Handler.hs) és isomòrfic al següent tipus:

    Request -> HandlerState -> IO (a, HandlerState)

    En realitat, la realització anterior del monad Handler consisteix en la construcció d'un:

    • context que afegeix un valor compartit de només lectura (de tipus Request) a un
    • context que afegeix un estat amb efectes de lectura i modificació (de tipus HandlerState) a un
    • monad de base IO.

    Però en Haskell ja existeixen paquets que ofereixen tipus que permeten afegir nous efectes a monads ja existents. En la realització anterior estem reinventant la roda !

    Com ja s'ha dit, aquests tipus són els anomenats transformadors de monads. El paquet transformers, a més de la classe MonadTrans, defineix varis transformadors de monads d'us general. En el nostre cas usarem els transformadors ReaderT r i StateT s.

    Però sovint resulta més còmode usar el paquet mtl. Aquest paquet reexporta els mateixos transformadors, però a més defineix classes que permeten incorporar de forma més genèrica els efectes d'una cadena de transformadors.

    En aquest apartat usarem el paquet mtl (mòduls Control.Monad.Reader i Control.Monad.State).

    Primer pas

    Completeu el mòdul Handler_T1 (fitxer Handler_T1.hs) on el tipus Handler és un àlias al stack de transformadors:

    type Handler = ReaderT Request (StateT HandlerState IO)
     
    Transformador ReaderT Request
    Transformador StateT HandlerState
    Monad IO
     

    Segon pas

    Completeu el mòdul Handler_T2 (fitxer Handler_T2.hs) on el tipus Handler és un nou tipus, envoltori del stack de transformadors:

    newtype Handler a = HandlerC (ReaderT Request (StateT HandlerState IO) a)

    En aquest cas, les instàncies de Functor, Applicative, Monad i MonadIO per al tipus Handler s'implementen sistemàticament a partir de les corresponents instàncies per al tipus envoltat pel constructor HandlerC. Bàsicament, extreient els arguments del constructor i envoltant els resultats amb el constructor.

    Usant l'extensió GeneralizedNewtypeDeriving el compilador pot derivar les instàncies indicades (amb la clàusula deriving) sense necessitat de implementar-les explícitament. Podeu observar com en el codi donat s'ha habilitat aquesta extensió (usant el corresponent pragma al principi del fitxer).

    ATENCIÓ: Per provar la nova versió del Handler, en l'aplicació de prova (l'exemple hello-2) caldrà importar el mòdul Handler_T1 o Handler_T2, en lloc del mòdul Handler.

    Realització d'un cas d'ús del monad Handler

    En aquest apartat es demana la realització d'una senzilla aplicació WEB que usa el monad Handler que heu implementat anteriorment.

    L'aplicació consisteix en un joc que processa una cadena de caràcters i produeix una puntuació (número enter) a partir de la cadena. Durant el processat el monad Handler manté un estat amb la puntuació actual i un flag que indica si el joc està activat o desactivat. El processat dels caràcters consisteix en:

    • * commuta el joc activat o desactivat,
    • + incrementa la puntuació si el el joc està activat, i
    • - decrementa la puntuació si el el joc està activat.
    • altres caràcters s'ignoren (no canvien el joc).

    La pàgina HTML de l'aplicació mostra l'estat actual del joc i un formulari que permeti a l'usuari introduir una cadena formada per caràcters com els anteriors. Inicialment el joc està desactivat i la puntuació és 0.

    En cada interacció es modifica l'estat adeqüadament i es redirigeix novament a la pàgina de l'aplicació.

    Així doncs, després de l'estat inicial (False, 0), si l'usuari introduís la seqüència de caràcters "*+-++*--*+" s'obtindria l'estat resultant (True, 3).

    El codi a completar de l'aplicació és el següent (copieu aquest codi en un fitxer en el mateix directori dat-prj/wai-intro on teniu el mòdul Handler):

    Podeu observar que l'estructura del codi és similar a la de l'exemple hello-2.hs.

    {-# LANGUAGE OverloadedStrings #-}

module Main
where
import           Network.Wai
import           Network.Wai.Handler.Warp (runEnv)

import           Handler

import           Data.Text (Text)
import qualified Data.Text as T

import qualified Text.Blaze.Html5 as H
import qualified Text.Blaze.Html5.Attributes as A

-- ****************************************************************

main :: IO ()
main = do
    -- runEnv :: Port -> Application -> IO ()
    runEnv 4050 $ dispatchHandler gameApp

-- ****************************************************************
-- Controller

gameApp :: Handler HandlerResponse
gameApp = onMethod
    [ ("GET", doGet)
    , ("POST", doPost)
    ]

doGet :: Handler HandlerResponse
doGet = ...

doPost :: Handler HandlerResponse
doPost = ...

-- ****************************************************************
-- View

htmlView :: GameState -> H.Html
htmlView game =
    H.docTypeHtml $ do
        H.head $
            H.title "A simple game ..."
        H.body $ do
            H.h1 $ H.text $ "Game state: " <> T.pack (show game)
            H.hr
            H.form H.! A.method "POST" H.! A.action "#" $ do
                H.p $ do
                    H.span "String to play:"
                    H.input H.! A.name "playText"
                H.input H.! A.type_ "submit" H.! A.name "ok" H.! A.value "Play"

-- ****************************************************************
-- Model

-- Tipus de l'estat
type GameState = (Bool, Int)

startState :: GameState
startState = (False, 0)

playChar :: Char -> GameState -> GameState
playChar ...

playString :: String -> GameState -> GameState
playString ...

playText :: Text -> GameState -> GameState
playText t = playString (T.unpack t)

    • Per mantenir l'estat del joc caldrà usar les funcions getSession i setSession amb el nom "playState".
    • Per obtenir la cadena de caràcters introduïda per l'usuari caldrà utilitzar la funció lookupPostParam amb el nom "playText".
