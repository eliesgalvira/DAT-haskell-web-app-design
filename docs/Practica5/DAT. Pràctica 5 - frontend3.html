En aquest pas, canviarem la manera com la nostra aplicació obté les dades.

  • Definirem un servei forumApiSrv que representa un client RESTful del servei WEB oferit pel backend del fòrum. Amb aquest client podrem fer sol·licituds de dades al servidor de manera senzilla, sense haver de tractar els detalls de l’API, com els mètodes HTTP i les URLs.
  • Realitzarem aquest servei mitjançant un servei de nivell inferior, integrat en AngularJS anomenat $http.
  • Utilitzarem la injecció de dependència (DI) d’AngularJS, tant per proporcionar el nostre servei forumApiSrv al controlador del component forumList, com per proporcionar el servei inferior $http d'AngularJS al nostre servei.
  • Utilitzarem la injecció de dependència també per proporcionar constants (URLs del servei WEB, d'autenticació, etc.) a les diferents parts de l'aplicació, obtenint una aplicació fàcilment configurable.

Definició de serveis

En primer lloc, usem l'API dels mòduls d'AngularJS per:

  • Amb el mètode constant, registrar un objecte amb els paràmetres de configuració de l'aplicació. Els arguments són el nom del servei 'config' i el valor.

  • Amb el mètode service, registrar un nou servei mitjançant una funció constructora (dins la funció, this es referirà al nou servei). Aquest servei proporciona les funcions que accedeixen l'API del webservice oferit pel backend del fòrum.

    Els arguments són el nom del servei 'forumApiSrv' i la funció constructora. Observeu com es declaren dues injeccions de dependències mitjançant arguments de la funció constructora:

    • config: Dependència amb l'objecte registrat de paràmetres de configuració.
    • $http: Dependència amb el servei $http. $http és el servei preregistrat d'AngularJS que permet fer peticions a servidors HTTP des del codi JavaScript.

app.js:

// Define the `forumsApp` module
angular.module('forumsApp', []);

// Register the `config` object in the `forumsApp` module. Provides the configuration params.
angular.module('forumsApp').
  constant('config',
    { apiUrl: 'http://soft0.upc.edu/~USER/practica4/forum-backend.cgi/api'
    }
  );

forum-api.service.js:

// Register the `forumApiSrv` service in the `forumsApp` module.
// Provides the access to the Forum Web Service.
angular.module('forumsApp').
  service('forumApiSrv', function(config, $http) {
    this.getForums = function() {
        return $http.get(config.apiUrl + '/forums').then(
            function (result) { return result.data; }
        );
    };
  });

Us dels serveis

Utilitzarem el servei forumApiSrv en el nostre controlador per fer les peticions i obtenir la llista de fòrums al nostre servidor WEB. AngularJS injecta els serveis per vosaltres, allà on els necessiteu.

Els serveis estan gestionats pel subsistema DI d'AngularJS. La injecció de dependència ajuda a que les vostres aplicacions WEB estiguin ben estructurades (per exemple, entitats separades per a la presentació, dades i control) i siguin dèbilment acoblades (les dependències entre entitats no són resoltes per les mateixes entitats, sinó pel subsistema DI). Com a resultat, les aplicacions són més fàcils de provar també.

forum-list.component.js:

angular.module('forumsApp').
  component('forumList', {
    templateUrl: 'forum-list.template.html',
    controller: function(forumApiSrv) {
      var self = this;
      self.forums = [];

      forumApiSrv.getForums().then(function(data) {
        self.forums = data.items;
      });
    }
  });

L’injector de dependència d’AngularJS proporciona serveis al vostre controlador quan es construeix el controlador. L’injector de dependència també s’ocupa de crear qualsevol dependència transitòria que pugui tenir el servei, ja que és freqüent que els serveis depenguin d’altres serveis (en la nostra aplicació, per exemple, podem observar com el servei forumApiSrv depèn dels serveis config i $http).

Tingueu en compte que els noms dels arguments són significatius, ja que l'injector els utilitza per cercar les dependències.

Convenció de noms amb prefix $

Podeu crear els vostres propis serveis amb qualsevol nom, però s'aconsella que no comencin amb el prefix $.

Com a convenció, els serveis integrats d'AngularJS, els mètodes de scope i alguns altres APIs d'AngularJS tenen el prefix $ davant del nom.

El prefix $ s'utilitza per proporcionar un espai de noms als serveis d'AngularJS. Per evitar col·lisions el millor és evitar posar noms als vostres serveis i models que comencin per $.

Si inspeccioneu una mica, també observareu algunes propietats que comencen amb $$. Aquestes propietats es consideren privades i no s’han d’accedir ni modificar.

Nota sobre la reducció de tamany (minification) del codi

Com que AngularJS infereix les dependències dels controladors i serveis a partir dels noms d’arguments de la funció constructora, si reduïu o minimitzeu el codi JavaScript, tots els arguments de les funcions també es podrien minimitzar i l’injector de dependència no seria capaç de identificar els serveis correctament.

Podem superar aquest problema anotant la funció amb els noms de les dependències, proporcionades com a cadenes, que no es poden minimitzar. Hi ha dues maneres de proporcionar aquestes anotacions d'injecció:

  • Creeu una propietat $inject en la funció controladora que conté una matriu de cadenes. Cada cadena de la matriu és el nom del servei a injectar per al paràmetre corresponent. En el nostre exemple, escriuriem:

    function ForumListController(forumApiSrv) {...}
ForumListController.$inject = ['forumApiSrv'];
...
.component('forumList', {..., controller: ForumListController, ...});

  • Feu servir una anotació en línia on, en lloc de només proporcionar la funció, proporcioneu una matriu. Aquesta matriu conté una llista dels noms del servei, seguida de la mateixa funció com a darrer element de la matriu.

    function ForumListController(forumApiSrv) {...}
...
.component('forumList', {..., controller: ['forumApiSrv', ForumListController], ...});

Ambdós mètodes funcionen amb qualsevol funció que pugui injectar AngularJS, de manera que correspon a la guia d'estil del vostre projecte decidir quina s'utilitza.

Quan s'utilitza el segon mètode, és habitual proporcionar la funció constructora en línia, quan es registra el controlador o servei:

.component('forumList', {..., controller: ['forumApiSrv', function (forumApiSrv) {...}], ...});

A partir d'ara, en el tutorial utilitzarem el mètode en línia.
