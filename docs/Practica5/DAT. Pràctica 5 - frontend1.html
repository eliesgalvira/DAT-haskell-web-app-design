Desenvolupament del frontend

En aquesta secció es descriurà, a través d'una sèrie de passos, el desenvolupament del frontend amb AngularJS.

En el codi font proveit pel professor en l'arxiu de projecte NO està inclòs el codi del frontend. Se us proposa que copieu el codi de l'últim d'aquests passos al direcori src/frontend del vostre projecte i completeu el desenvolupament amb tota la funcionalitat requerida.

Funcionament bàsic d'AngularJS

La següent figura mostra una aplicació AngularJS amb els seus components MVC. Un cop s'accedeix la pàgina HTML de l'aplicació, el codi JavaScript (model + controladors) i les plantilles (vistes) es carreguen en el dispositiu de l'usuari (navegador o móbil) i s'executa. El codi JavaScript serà el responsable de modificar dinàmicament la pàgina inicialment carregada.

Com pot observar-se, part del model interacciona amb el servidor a través d'un servei WEB amb estil REST.

En aquest primer pas construirem una pàgina dinàmica en la que es mostra una llista generada a partir de JS.

La pàgina serà una plantilla AngularJS. Les plantilles són bàsicament pàgines HTML amb directives que AngularJS processarà, modificant el seu contingut i lligant accions a funcions del(s) controlador(s) de l'aplicació. En la pàgina, evidentment, caldrà incloure el codi d'AngularJS i el codi de l'aplicació.

El primer que cal considerar es com s'inicia l'execució de l'aplicació (bootstraping). La forma més fàcil es usant la directiva ngApp en la plantilla de la pàgina. En aquest exemple s'usa la directiva en forma d'atribut:

index.html:

<html ng-app="forumsApp">
<head>
...
<script type="text/javascript" src="http://ajax.googleapis.com/ajax/libs/angularjs/1.7.5/angular.min.js"></script>
<script type="text/javascript" src="app.js"></script>
...
</head>
...
</html>

El valor de l'atribut ng-app és el nom del mòdul que es carrega i inicialitza. Aquesta directiva s'usa per indicar l'element que AngularJS considerarà com l'element arrel de la nostra aplicació. Això dona als desenvolupadors la llibertat de dir a AngularJS si la pàgina HTML sencera o només un troç ha de tractar-se com una aplicació AngularJS.

Vistes i plantilles

En AngularJS, la vista és una projecció del model a través de la plantilla HTML. Això vol dir que quan el model canvia, AngularJS refresca els corresponents punts de lligam (binding points), que modifiquen la vista.

La vista és construida per AngularJS a partir de la següent plantilla:

index.html:

...
<body ng-controller="ForumListController">
  ...
  <table class="table table-striped">
    <thead><tr><th>Títol</th><th>Descripció</th></tr></thead>
    <tbody>
      <tr ng-repeat="t in forums">
        <td>{{t.title}}</td><td>{{t.description}}</td>
      </tr>
    </tbody>
  </table>
  ...
</body>
...

Observeu la directiva ngController, que associa el controlador ForumListController a l'element <body>. Aleshores, AngularJS:

  • ForumListController s'encarrega de controlar el subarbre DOM sota (i incloent-lo) l'element <body>.
  • Les expresions que hi ha a la plantilla (dins de directives o entre claudàtors) denoten lligams, que es refereixen al model de l'applicació, i que està definit en el nostre controlador ForumListController.

Observeu també la directiva ngRepeat i les dues expressions AngularJS:

  • L'atribut ng-repeat="t in forums" en l'element <tr> és una directiva AngularJS de repetició. La directiva indica a AngularJS que creï un element <tr> per a cada fòrum en la llista, usant l'element <tr> com la plantilla.
  • Les expresions entre claudàtors ({{t.title}} i {{t.description}}) seràn sustituïdes pels valors de les expresions.

Model i Controladors

El model (un simple array de fòrums en notació literal) és instanciat dins del controlador ForumListController. El controlador és simplement una funció constructora que té el $scope com a paràmetre:

app.js:

// Define the `forumsApp` module
forumsApp = angular.module('forumsApp', []);

// Define the `ForumListController` controller on the `forumsApp` module
forumsApp.controller('ForumListController', function($scope) {
    $scope.forums = [
        { id: 1, title: "Fòrum de prova 1", description: "Aquest és un fòrum de prova." },
        { id: 2, title: "Fòrum de prova 2", description: "Aquest és un fòrum de prova."},
        { id: 3, title: "Fòrum de prova 3", description: "Aquest és un fòrum de prova."}
    ];
});

Hem declarat un controlador anomenat ForumListController i registrat en un mòdul AngularJS, forumsApp. Observeu que la directiva ngApp (en l'element <html>) especifica el nom del mòdul forumsApp com el mòdul a carregar quan es fa el bootstrapping de l'applicació.

Encara que per ara fa poca cosa, el controlador juga un paper crucial. Oferint context per al nostre model de dades, el controlador estableix un lligam (data-binding) entre el model i la vista. Els aspectes de presentació, dades i lògica queden conectats de la següent manera:

  • La directiva ngController, en l'element <body>, referencia el nom del nostre controlador, ForumListController (definit en el fitxer JavaScript app.js).
  • El controlador ForumListController adjunta les dades dels fòrums a l'àmbit $scope que s'injecta a la nostra funció controladora. Aquest àmbit extén per prototipat l'àmbit arrel que s'ha creat quan l'aplicació ha sigut inicialitzada. Aquest àmbit del controlador és el de tots els lligams dins de l'element <body ng-controller="ForumListController">.

Àmbits (Scopes)

El concepte d'scope en AngularJS és crucial. Un scope es pot veure com el pegament que permet que la plantilla, el model i el controlador operin conjuntament. AngularJS usa els scopes per mantenir els models i les vistes separats però amb sincronia. Qualsevol canvi en el model queda reflectit en la vista; qualsevol canvi que succeeix en la vista queda reflectit en el model.

Per saber més sobre els scopes d'AngularJS, veieu la documentació d'AngularJS.

Els scopes d'AngularJS extenen per prototipat el scope pare, cap amunt fins el root scope creat per l'aplicació. Per tant, assignant valors directament als scopes fàcilment podem compartir dades entre diferents parts de la pàgina i crear aplicacions interactives. Encara que aquest plantejament funciona per a aplicacions petites, en canvi ens porta a una acoplament massa fort entre les parts i a una dificultat per a raonar sobre els canvis en el model.
