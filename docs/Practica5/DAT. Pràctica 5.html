Pràctica 5: Single Page Application

Objectius

En la pràctica 5 s'haurà de realitzar una aplicació SPA (Single Page Application) que interaccioni amb un servei WEB amb estil REST ofert per un servidor de fòrums.

La funcionalitat oferta per aquesta aplicació serà molt similar a la que ofereix la pràctica anterior de fòrums, però amb una implementació molt diferent: Tota la presentació i interacció amb l'usuari és tractada localment en el client (navegador).

Per a realitzar aquesta pràctica utilitzareu miso (versió 1.9), un framework per al desenvolupament en Haskell d'aplicacions de costat client (SPA).

Arquitectura de la aplicación

El siguiente diagrama muestra como interactúan las distintas partes de que se compone la aplicación de esta práctica.

Cal distingir els fluxos d'interacció següents:

  1. L'usuari visita l'URL http://localhost:8008/index.html corresponent a la pàgina principal del frontend de l'aplicació (Static URLs).

    Aquesta pàgina i el codi javascript del frontend és el contingut estàtic obtingut a partir de la compilació de l'aplicació SPA realitzada amb Haskell.

    Un cop carregada la pàgina principal i els continguts relacionats, s'executa el codi del frontend.

  2. El frontend interactua amb l'API REST ofert pel backend (API URLs). En les interaccions directes entre el JS del frontend i el backend, els continguts transferits són JSON.

  3. Quan l'usuari necessiti autenticar-se haurà de visitar, des de la pàgina HTML, l'enllaç a la URL del servei d'autenticació (Auth URLs). Aquest servei ofereix al navegador una interfície HTML clàssica.

    El servei d'autenticació del backend emmagatzema la URL de retorn (la pàgina que conté l'enllaç). Aquesta URL s'obté del paràmetre redirect_url de la petició HTTP desencadenada per la visita a l'enllaç.

  4. Un cop autenticat l'usuari, el backend registra l'identificador de l'usuari a la sessió amb el navegador i redirigeix ​​el navegador a la URL del frontend (emmagatzemada al pas anterior).

    El manteniment de la sessió entre el navegador i el backend es realitza mitjançant cookies que seran incloses de forma implícita en cadascuna de les peticions que el navegador faci al backend.

  5. Un cop recarregat el frontend i executat de nou, tornarà a interactuar amb l'API REST (accedint a les API URLs). Ara, en canvi, a la sessió estarà inclòs l'identificador de l'usuari autenticat.
